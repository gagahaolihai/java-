# 项目文档索引

每个项目在动手写代码**之前**先写完这里的需求与表设计。理由：

- 面试官问"你为什么这么设计"，答案要能指回文档
- 边写边改设计 = 后期大量返工
- 文档本身就是"需求分析能力"的证明

| [项目二-企业后台管理系统.md](./项目二-企业后台管理系统.md) | 阶段二（W6） | Spring Boot 单体后端 | REST 规范、RBAC、MyBatis |

## 写文档的最小结构（每个项目都要有）

1. **项目简介**：一句话说清做什么、给谁用
2. **技术栈**：具体到版本
3. **角色与用例**：谁可以做什么
4. **功能清单**：分模块列出，标注优先级（P0 必做 / P1 加分 / P2 不做）
5. **数据库设计**：表名、字段、类型、约束、索引、建表 DDL
6. **接口清单**：方法、路径、入参、出参、错误码
7. **核心流程**：用 mermaid 时序图画出关键链路（下单、借书、登录鉴权）
8. **非功能需求**：性能目标、安全要求、部署方式
9. **验收清单**：逐条 checkbox，能勾完才算项目完成
