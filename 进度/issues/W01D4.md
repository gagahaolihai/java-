## 二、动手练习

### 第 1 步：数据模型

```java
public record Student(String name, String className, int age,
                      Map<String, Integer> scores) {     // 科目 -> 分数
    public int total() { return scores.values().stream().mapToInt(Integer::intValue).sum(); }
    public double average() { return scores.values().stream().mapToInt(Integer::intValue).average().orElse(0); }
    public boolean hasSubject(String subject) { return scores.containsKey(subject); }
}
```

`Main` 里造 **至少 20 个学生 / 4 个班级 / 5 个科目**，分数用 `new Random(42)` 生成（**固定种子**，保证每次运行结果一致，方便对答案）。

### 第 2 步：12 项统计（`ScoreAnalyzer` 静态方法）

| # | 方法签名 | 要用到的 API |
|---|---|---|
| 1 | `List<Student> filterByClass(List<Student>, String cls)` | `filter` |
| 2 | `List<String> namesOfTopN(List<Student>, int n)` | `sorted` + `limit` + `map` |
| 3 | `double averageOfSubject(List<Student>, String subject)` | `filter` + `mapToInt` + `average` + `orElse` |
| 4 | `Map<String, List<Student>> groupByClass(List<Student>)` | `groupingBy` |
| 5 | `Map<String, Double> avgByClass(List<Student>)` | `groupingBy` + `averagingDouble` |
| 6 | `Map<String, Long> countByClass(List<Student>)` | `groupingBy` + `counting` |
| 7 | `Map<String, Long> scoreDistribution(List<Student>, String subject)` | 分段（<60/60-69/70-79/80-89/90+）+ `groupingBy` |
| 8 | `Map<Boolean, List<Student>> passOrFail(List<Student>, String subject, int passLine)` | `partitioningBy` |
| 9 | `Optional<Student> topStudent(List<Student>)` | `max` + `Comparator` |
| 10 | `Set<String> allSubjects(List<Student>)` | `flatMap` + `distinct` + `collect(toSet())` |
| 11 | `String classNamesJoined(List<Student>)` | `map` + `distinct` + `joining(", ")` |
| 12 | `Map<String, IntSummaryStatistics> statsBySubject(List<Student>)` | `flatMap` + `groupingBy` + `summarizingInt` |

**第 7 项是重点**：不允许写 `if/else` 链，必须用一个 `Function<Student, String> level()` 提取分段，再 `groupingBy(level, TreeMap::new, counting())` 让输出有序。

### 第 3 步：必踩的坑 —— `toMap` 的 key 冲突

```java
// 意图：得到 姓名 -> 总分
Map<String, Integer> m = students.stream()
        .collect(Collectors.toMap(Student::name, Student::total));
```
**构造两个同名学生**，跑一遍，你会得到：
```
java.lang.IllegalStateException: Duplicate key ...
```
三种正确解法，都写一遍并注明适用场景：

```java
// 方案 1：保留后者
Collectors.toMap(Student::name, Student::total, (oldV, newV) -> newV)
// 方案 2：后者覆盖但提示
Collectors.toMap(Student::name, Student::total, (o, n) -> { System.out.println("重名: " + o); return n; })
// 方案 3：合并
Collectors.toMap(Student::name, Student::total, Integer::sum)
```
**再踩一个**：`toMap` 的 **value 为 null** 时会抛 NPE（`HashMap.merge` 的锅）。用 `HashMap::new` 也不行，要改用 `forEach` 或 `Collectors.toMap` + 过滤 null。

### 第 4 步：`Optional` 的正确姿势

```java
// ❌ 反面教材
Optional<Student> opt = topStudent(list);
if (opt.isPresent()) { return opt.get().name(); } else { return "无人"; }

// ✅ 正确
return topStudent(list).map(Student::name).orElse("无人");

// ✅ 找不到就抛业务异常
return topStudent(list).orElseThrow(() -> new NoSuchElementException("没有任何学生"));

// ✅ 有条件才取值
return topStudent(list).filter(s -> s.average() >= 90)
                       .map(Student::name)
                       .orElse("没有优秀学生");
```

### 第 5 步：Stream 的惰性求值验证

```java
Stream.of("a", "b", "c")
      .peek(s -> System.out.println("遇到: " + s))   // 中间操作，不会立刻执行
      .filter(s -> !s.equals("b"));
System.out.println("=== 上面没打印任何东西，因为没有终止操作 ===");

// 加上终止操作才会跑
Stream.of("a", "b", "c")
      .peek(s -> System.out.println("遇到: " + s))
      .filter(s -> !s.equals("b"))
      .count();
```
再验证**短路**：
```java
Stream.of(1, 2, 3, 4, 5)
      .peek(System.out::println)
      .anyMatch(i -> i > 2);      // 只会打印 1 2 3 —— 找到就停
```

### 第 6 步：`reduce` 与基本类型流

```java
// 求和：三种写法对比
int sum1 = students.stream().mapToInt(Student::total).sum();                 // ✅ 推荐，无装箱
int sum2 = students.stream().map(Student::total).reduce(0, Integer::sum);    // 有装箱开销
int sum3 = students.stream().map(Student::total).reduce(0, (a, b) -> a + b);

// 求最大值的 reduce 版本（注意返回 Optional，因为空流无解）
Optional<Integer> max = students.stream().map(Student::total).reduce(Integer::max);
```

### 第 7 步：反例清单（笔记重点）

写出 **4 个不该用 Stream 的场景**，每条给一段对照代码：
1. 简单循环 + `break`/`continue` → 用 for 更清楚
2. 需要在 lambda 里修改外部局部变量（`int` 计数）→ 编译不过（要求 effectively final），用 `for` 或 `AtomicInteger`（但后者是坏味道）
3. 有复杂异常处理逻辑 → try/catch 塞进 lambda 会让代码难读
4. 性能敏感的热点循环（基本类型大数组）→ 普通 for 更快
5. （加分）`parallelStream` 用了非线程安全的共享容器 → 结果错乱，写出复现代码
