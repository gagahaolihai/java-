### 第 1 步：`Result<T>` —— 这个类你后面三个月会一直用

public final class Result<T> {

    private final T data;
    private final String code;
    private final String message;

    private Result(boolean success, T data, String code, String message) { ... }

    public static <T> Result<T> ok(T data) { ... }
    public static <T> Result<T> ok() { ... }
    public static <T> Result<T> fail(String code, String message) { ... }
    public static <T> Result<T> fail(ErrorCode code) { ... }   // 配合下面的枚举

    public boolean isSuccess() { ... }
    public T getData() { ... }                 // 失败时应抛 IllegalStateException，而不是返回 null
    public T orElse(T defaultValue) { ... }
    public <R> Result<R> map(Function<T, R> mapper) { ... }    // 失败时直接透传，不执行 mapper
    public <R> Result<R> flatMap(Function<T, Result<R>> mapper) { ... }
    public Result<T> peek(Consumer<T> action) { ... }          // 成功时看一眼，不改类型

### 第 4 步：PECS 两个方向（**今天的重点**）

```java
public final class PecsDemo {
    // Producer Extends：只从 src 读，所以可以用 ? extends Number
    // 好处：传入 List<Integer> 也行（List<Integer> 是 List<? extends Number> 的子类型）
    public static double sum(List<? extends Number> src) { ... }

    // Consumer Super：只往 dst 写，所以可以用 ? super Integer
    // 好处：传入 List<Number> 或 List<Object> 都行
    public static void fill(List<? super Integer> dst, int n) { ... }

    // 既是生产又是消费：只能老老实实写 List<T>（不要用通配符）
    public static <T> void copy(List<? extends T> src, List<? super T> dst) { ... }
}
```
在 `Main` 里验证：
```java
List<Integer> ints = List.of(1, 2, 3);
System.out.println(PecsDemo.sum(ints));         // ✅ 能编译

List<Object> objs = new ArrayList<>();
PecsDemo.fill(objs, 5);                          // ✅ 能编译

// 反过来试，体会编译错误：
// PecsDemo.sum(new ArrayList<Object>());        // ❌ 为什么不行？
// List<? extends Number> l = ...; l.add(1);     // ❌ 为什么不行？
```

### 第 5 步：亲手证明类型擦除

```java
public class ErasureProof {
    public static void main(String[] args) {
        List<String> a = new ArrayList<>();
        List<Integer> b = new ArrayList<>();
        System.out.println(a.getClass() == b.getClass());          // true
        System.out.println(a.getClass().getName());                // java.util.ArrayList

        // 反射绕过泛型检查 —— 能成功，说明运行期确实没有泛型信息
        try {
            a.getClass().getMethod("add", Object.class).invoke(a, 123);
        } catch (Exception e) { e.printStackTrace(); }
        System.out.println(a);                                     // [123] 竟然加进去了

        // 取出来时才炸
        try {
            String s = a.get(0);   // ClassCastException
        } catch (ClassCastException e) {
            System.out.println("擦除的代价：" + e.getMessage());
        }
    }
}
```
再补一组对照：
```java
class Box<T> { T value; }
class StringBox extends Box<String> {}
// 用反射打印：Box.class.getTypeParameters().length       → 1
//            StringBox.class.getGenericSuperclass()       → Box<java.lang.String>（签名里还留着）
```
**结论写进笔记**：泛型是**编译期**的语法糖，运行期被擦除；泛型信息在 `Class` 的 **Signature** 属性里以元数据形式保留，所以反射能拿到 `Box<String>`，但拿不到具体实例的类型参数。
