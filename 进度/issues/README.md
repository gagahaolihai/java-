# 每日任务书（可直接当 GitHub Issue 用）

这里是按天拆好的任务书。每个文件就是当天 GitHub Issue 的正文。

## 怎么用

| 方式 | 做法 | 适合 |
|---|---|---|
| **① 手动建 Issue** | 打开文件 → 全选复制 → GitHub `New issue` → 粘贴 → 标题用文件里的 `# 标题` | 现在就能用 |
| **② 助手批量建** | 说一句"按 `进度/issues/` 里的文件批量建 Issue"，助手用 GitHub MCP 建 | token 权限修好后 |
| **③ 本地直接看** | 开着文件写代码，不用管 GitHub | 只想专心学习时 |

> 推荐**①和③并行**：Issue 用作"今天要做完这些"的清单，关闭 Issue 的那一刻就是今天的收工仪式。

## 命名规则

```
W<周号两位>D<天号一位>.md      例：W01D3.md、W03D5.md
```

## 每周的固定节奏

| 天 | 主题 | 备注 |
|---|---|---|
| D1 | 新知识点 A | |
| D2 | 新知识点 B | |
| D3 | 新知识点 C | 通常是本周最硬的一天 |
| D4 | 新知识点 D | |
| D5 | 新知识点 E | |
| D6 | 工程化 / 设计规范 | |
| D7 | **综合练习 + 周复盘** | 必做：写周报、更新 README 看板、打 tag `week-NN` |

## 每天收工前必须做的三件事

1. 勾完文件里的「验收标准（DoD）」
2. 填「收工记录」的完成度百分比和卡点
3. `git commit` 并推送，然后关闭对应的 GitHub Issue
